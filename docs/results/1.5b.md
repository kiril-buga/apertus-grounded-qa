# Results: Apertus 1.5B (Kaggle T4)

Model `swiss-ai/Apertus-v1.1-1.5B-Instruct`, config `configs/apertus1p5b_dev.yaml`, fp16 on one Tesla T4.
Test split: 200 questions (140 answerable, 60 unanswerable via context swap), never seen in training.
All tables are copied from the notebook outputs saved in this repo's history (`git show <commit>:notebooks/run_pipeline.ipynb`).
Values are percentages with 95% bootstrap CIs; Δ columns are paired differences against the base model, and `*` marks
a CI that excludes 0.

The metric changed between runs, so compare models **within** a table, not across tables:

| Metric version | Used in | What changed |
|---|---|---|
| v1 | runs 1–2 | claim support + consistency with the reference (precision only) |
| v2 | runs 3–4 | adds reference coverage (recall); short answers judged together with their question; headline also needs ≥ 50% coverage; more refusal patterns |

## Run 4: DPO trains cleanly but changes nothing (Kaggle version 9, commit `9eef538`)

SFT and its preference samples were restored from version 8 (`REDO_FROM = "prefs"`), so only the pairs, DPO and the
evaluation are new. Reward v3: harmonic mean of on-topic precision (claims supported by the page *and* by the
reference) and coverage. Pairs from the model's own samples only (no reference fallback), `min_gap` 0.3. DPO: 1,123
preference prompts → 379 pairs (373 answerable, 6 unanswerable); 744 prompts were skipped because their four samples
scored within 0.3 of each other. β=0.3, lr 2e-5, 2 epochs, 8 pairs per step (about 90 steps, 25 min). Metric v2.

Training: train loss 0.693 → 0.61 and train reward accuracy about 0.85 in epoch 2, but on the 18 validation pairs eval
loss only moved from 0.681 to 0.673 and reward accuracy stayed at 0.50–0.61. The jump in epoch 2 is the model seeing
the same pairs again, not generalising.

Base and SFT are the same answers as run 3. Every DPO number is within two points of SFT, in both directions, and
answers grew only slightly (1.47 → 1.65 claims). Neither shortcut from runs 2 and 3 appeared, but nothing improved
either: with a third of the prompts giving a usable pair and small reward gaps within each pair, the signal was too
weak to move the model.

answers it rejects, ten of them with reference coverage 0 or 0.5, such as "On March 7." or "A browser console.". On
these rows the headline errs on the strict side: it undercounts correct short or partial answers instead of rewarding
evasive ones. With only five rejected answers in the sample, that doesn't prove it can't be gamed.

## SFT is reproducible

Grounded accuracy of SFT across three independent trainings: 62.5% (run 1), 62.0% (run 2), 63.5% (run 3, metric v2),
with 98.3% correct abstention each time (run 4 reused run 3's SFT) and no refusals of answerable questions.
