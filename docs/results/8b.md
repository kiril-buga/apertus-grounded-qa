# Results: Apertus 8B (QLoRA, RTX 4080 Super)

Model `swiss-ai/Apertus-8B-Instruct-2509`, config `configs/apertus8b_16gb.yaml`, run with
`python scripts/run_sft_eval.py` on one RTX 4080 Super (16 GB, WSL2). The raw outputs are in
[`results/8b/`](../../results/8b/): the table, the SFT training log, every verified answer, and the GPU, library
versions and step timings (`run_info.json`).

Same 200 test questions (140 answerable, 60 unanswerable), same training data and the same SFT recipe as the 1.5B
runs (LoRA r=16, α=32, all linear layers, lr 2e-4, effective batch 16, 2 epochs), and the same metric (v2, see
[`1.5b.md`](1.5b.md)). What differs: the model is loaded in 4 bits (NF4) for training and for both evaluations, and
the batch is 1 × 16 gradient-accumulation steps instead of 4 × 4. DPO was not run on 8B.

## SFT

| Metric | base | sft | Δ sft vs base |
|---|---|---|---|

| Refuses when answerable ↓ | 0.7 [0.0, 2.3] | 0.7 [0.0, 2.3] | +0.0 [+0.0, +0.0] |
| Abstention F1 ↑ | 49.4 [35.2, 62.5] | 98.3 [95.5, 100.0] | +49.0 [+36.8, +62.5] * |
| Claims supported by context ↑ | 74.8 [68.5, 80.7] | 90.1 [86.4, 94.1] | +15.3 [+8.9, +22.2] * |
| Answers with every claim supported ↑ | 70.9 [63.7, 77.2] | 87.1 [81.5, 92.4] | +16.2 [+7.9, +24.3] * |

| Token F1 vs reference ↑ | 67.6 [63.8, 71.5] | 77.3 [73.8, 80.9] | +9.7 [+6.6, +12.9] * |
| Claims per answer | 1.66 | 1.59 | – |

Values are percentages with 95% bootstrap CIs (1000 resamples). Examples per run: base: 200, sft: 200.
Δ columns are paired bootstrap differences on shared examples; * marks a CI that excludes 0.

Every gain except over-refusal has a CI that excludes 0. The base model still answers 40 of 60 unanswerable
questions, with invented details: MESH "stands for 'Make Every Situation Holy'", and a made-up lyric for Semisonic's
"Closing Time". After SFT, one answerable question gets the abstention string (as with the base model, 1 of 140),
and one unanswerable question gets an answer. That question asks what "the context is primarily discussing", which
the context swap turns answerable (a known limitation of the data, see the README).

Training: 188 steps in 52 minutes, peak GPU memory 7.1 GB (measured in the `--check` run with the same settings).
Validation loss went 0.182 (step 50) → 0.177 (100) → 0.176 (150) → 0.177 (188); the step-150 checkpoint is the one
kept. The second epoch added almost nothing, so one epoch would likely do for this model.

## Next to 1.5B

Same test questions and metric; the 1.5B numbers are run 3 in [`1.5b.md`](1.5b.md) (fp16 on a T4).

| | 1.5B base | 1.5B SFT | 8B base | 8B SFT |
|---|---|---|---|---|
| Grounded accuracy | 22.5 | 63.5 | 37.0 | 65.0 |
| Abstains when unanswerable | 10.0 | 98.3 | 33.3 | 98.3 |
| Refuses when answerable | 0.0 | 0.0 | 0.7 | 0.7 |
| Claims supported by context | 67.4 | 88.9 | 74.8 | 90.1 |
| Consistent with reference | 41.4 | 62.1 | 53.2 | 66.9 |
| Covers the reference | 63.0 | 67.7 | 65.9 | 73.0 |
| Token F1 vs reference | 56.7 | 72.2 | 67.6 | 77.3 |
| Claims per answer | 2.32 | 1.47 | 1.66 | 1.59 |

- The 8B base model is clearly better than the 1.5B base model before any training: grounded accuracy 37.0 vs 22.5
  and abstention 33% vs 10%, with non-overlapping CIs.
- After SFT the two land close together. 8B is ahead on every answer-quality metric, by 0.6 to 5.3 points, but the
  CIs overlap; it also refuses one answerable question that 1.5B answered. A paired test isn't possible here because the 1.5B answers live in Kaggle outputs, not in this repo.
- Both sizes reach 98.3% abstention after SFT, so the extra capacity shows up in how closely the answers match the
  reference (consistency +4.8, coverage +5.3, token F1 +5.1), not in knowing when to abstain.
- One possible reason the headline barely moves with scale: on the 40 human-labelled answers, metric v2 rejected 12
  of 35 correct ones, mostly short answers with low reference coverage. A stricter-than-human metric caps the
  headline for both models. I haven't tested this on 8B answers; labelling a sample of them would.
